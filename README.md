# Content Share

Трансляция фильмов, музыки и фото с ПК (Windows/Linux) на телевизоры LG webOS — аналог SmartShare, но с
корректной обработкой любых форматов видео.

```
server/          Rust-сервер (axum + tokio + ffmpeg)
  admin/         панель управления (http://localhost:8200/admin)
webos-client/    приложение для webOS (HTML/JS, ES5)
webos-discovery/ служба webOS (Node.js) для поиска серверов по UDP
```

## Как воспроизводится видео не в MP4

Для каждого файла сервер вызывает `ffprobe` и выбирает самый качественный путь:

| Режим | Когда | Что происходит | Качество |
|---|---|---|---|
| **Direct** | контейнер MKV/MP4/WebM и кодеки поддерживаются ТВ | файл отдаётся как есть (HTTP Range, нативная перемотка) | оригинал |
| **Remux** | видео H.264/HEVC/MPEG-2 подходит, но контейнер (AVI, TS, WMV, FLV…) или звук (DTS, TrueHD, FLAC, Opus) — нет | видео копируется без перекодирования (`-c:v copy`), звук → AC3 5.1 / AAC, упаковка в HLS (MPEG-TS) | видео без потерь |
| **Transcode** | видеокодек не поддерживается (H.264 Hi10P, DivX/Xvid, VC-1, WMV, AV1 на старых ТВ, 4:2:2) | перекодирование в H.264 или HEVC: NVENC / Quick Sync / AMF / VAAPI, иначе x264. HDR→SDR тонмаппинг, деинтерлейс, вшивание PGS/VobSub субтитров | CRF 20, до 40 Мбит/с (настраивается) |

Детали:

- **Перемотка в потоке** — ffmpeg перезапускается с `-ss`. Для remux старт выравнивается по ближайшему
  ключевому кадру (через `ffprobe -read_intervals`), и сервер сообщает клиенту точное время начала, поэтому
  позиция и субтитры не «уезжают». Клиент показывает время как `offset + currentTime`.
- **Расход диска** — ffmpeg приостанавливается (SIGSTOP на Linux, SuspendThread на Windows), когда опережает
  плеер примерно на 80 секунд. Просмотренные сегменты удаляются. Сессия закрывается через 60 секунд без запросов.
- **Автоматический откат** — если ТВ не смог воспроизвести файл напрямую (ошибка, нет картинки, не стартовал),
  клиент переключается на поток. Если remux не пошёл — на полное перекодирование. Если аппаратный
  кодировщик не запустился — сервер сам пробует x264.
- **Звуковые дорожки** — выбор любой дорожки (через `audioTracks`, если ТВ это поддерживает, иначе через remux).
- **Субтитры** — встроенные текстовые (SRT/ASS/mov_text) и внешние файлы `фильм.rus.srt` конвертируются
  в WebVTT; кодировка CP1251 определяется автоматически. Клиент рисует их сам. Графические субтитры
  (PGS, VobSub) вшиваются в видео.
- **Продолжение просмотра** — позиция сохраняется на ТВ, при открытии предлагается продолжить.

## Сборка и запуск сервера

Нужны Rust 1.85+ и [ffmpeg](https://ffmpeg.org/download.html) (с ffprobe).

```sh
cargo build --release
./target/release/webos-content-share          # Windows: target\release\webos-content-share.exe
```

ffmpeg ищется так: путь из настроек → рядом с исполняемым файлом (`ffmpeg.exe` или `ffmpeg/bin/ffmpeg.exe`) → `PATH`.

- Windows: `winget install Gyan.FFmpeg` или распакуйте сборку с gyan.dev рядом с `webos-content-share.exe`.
- Linux: `sudo apt install ffmpeg` (для VAAPI пользователь должен входить в группу `render`).

При первом запуске откроется панель управления `http://localhost:8200/admin`, где можно:

- добавлять и удалять медиапапки (есть выбор папки через «Обзор…»);
- указать, что умеет ваш ТВ (HEVC, VP9, AV1, DTS, TrueHD, 4K);
- настроить перекодирование: аппаратное ускорение, кодек, качество, битрейт;
- смотреть и останавливать активные трансляции.

Панель доступна только с самого компьютера. Телевизорам доступен лишь API для чтения медиатеки.

Параметры: `--port N`, `--config ФАЙЛ`, `--no-browser`. Настройки хранятся в
`%APPDATA%\WebOSContentShare\config.json` (Windows) или `~/.config/WebOSContentShare/config.json` (Linux).
Подробные логи: переменная окружения `RUST_LOG=debug`.

Брандмауэр должен пропускать входящие подключения на порт 8200 (TCP, медиатека) и 8201 (UDP, автопоиск);
Windows спросит разрешение при первом запуске.

### Linux: автозапуск через systemd

```ini
# ~/.config/systemd/user/content-share.service
[Unit]
Description=Content Share media server
After=network-online.target

[Service]
ExecStart=/opt/content-share/webos-content-share --no-browser
Restart=on-failure

[Install]
WantedBy=default.target
```

`systemctl --user enable --now content-share`

## Клиент на телевизоре

**Вариант 1 — без установки:** откройте во встроенном браузере ТВ адрес `http://<IP-компьютера>:8200/app/`.

**Вариант 2 — приложение** (удобнее: пульт, кнопка «Назад», запуск из меню):

1. Установите на ТВ приложение **Developer Mode** из LG Content Store и включите режим разработчика.
2. Установите [webOS TV CLI](https://webostv.developer.lge.com/develop/tools/cli-installation)
   (`npm install -g @webos-tools/cli`).
3. Подключите ТВ: `ares-setup-device` (IP телевизора, пароль из Developer Mode).
4. Соберите пакет (приложение вместе со службой поиска) и установите его:

   ```sh
   ares-package webos-client webos-discovery
   ares-install --device tv com.contentshare.player_1.0.0_all.ipk
   ```

### Поиск сервера

Приложение находит сервер само, адрес вводить не нужно:

1. При запуске проверяется последний использованный сервер.
2. Если он не отвечает (например, у ПК сменился IP), служба `webos-discovery` рассылает UDP-broadcast на
   порт 8201. Каждый сервер отвечает своим именем, ID и HTTP-портом, поэтому находятся серверы на любом
   порту. Это занимает около 1,5 секунды.
3. Без службы (веб-версия `/app/` в браузере ТВ) — HTTP-сканирование подсети телевизора на порту 8200.

Если найден единственный сервер или тот же, что и раньше (по ID, даже с новым адресом), приложение
подключается к нему без вопросов. Иначе показывает список. Пока ничего не найдено, поиск повторяется
каждые 15 секунд. Адрес по-прежнему можно ввести вручную.

На всех экранах есть кнопка «Назад» (для указки Magic Remote и браузера), она работает так же, как кнопка
«Назад» на пульте.

Управление с пульта:

| Кнопка | Действие |
|---|---|
| ◀ ▶ | перемотка (10 с, при удержании 30 и 60 с) |
| ⏪ ⏩ | перемотка на 1 минуту |
| OK | пауза |
| ▼ | выбор звуковой дорожки и субтитров |
| CH+ / CH− | следующий / предыдущий файл в папке |
| Назад | выход из плеера (позиция сохраняется) |

## HTTP API

| Метод | Назначение |
|---|---|
| UDP `8201`: `WEBOS-CONTENT-SHARE-DISCOVER` | ответ `{"app","id","name","port","version"}` — автопоиск |
| `GET /api/info` | ID, имя и версия сервера |
| `GET /api/browse?root=&path=` | содержимое папки; без `root` — список медиапапок |
| `GET /api/media?root=&path=` | дорожки, субтитры, `direct`, причины, режим потока |
| `GET /api/raw/{root}/{path}` | оригинальный файл с поддержкой Range |
| `GET /api/stream/start?root=&path=&start=&audio=&burn=&mode=auto\|transcode&client=` | запуск HLS-трансляции |
| `GET /api/stream/{id}/index.m3u8`, `…/segNNNNN.ts`, `…/keepalive`, `…/stop` | HLS-сессия |
| `GET /api/thumb?root=&path=&size=` | превью (JPEG, кешируется) |
| `GET /api/subs?root=&path=&id=` | субтитры в WebVTT |

cargo test
